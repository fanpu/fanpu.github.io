InfiniBand Field Guide
A friendly guide for ML people

How InfiniBand moves your gradients

When thousands of GPUs train one model, they spend a lot of time swapping data. InfiniBand is the network most big clusters use for that. This page walks through how it works, one picture at a time. No networking background needed.

Part 1

The big idea

Ethernet, the network your laptop uses, was built for the internet. Nobody owns the whole internet, so every switch has to figure things out on its own, and losing a packet now and then is treated as normal.

InfiniBand was built for a different world. One owner, one building, one job, which is moving memory from one machine to another as fast as possible. Once you can assume a single owner, you can make very different design choices. The rest of this page is about those choices.

The whole thing in one line Smart network cards, dumb fast switches, one central brain that sets everything up, and links that never throw packets away.
Part 2

Meet the cast

THE NETWORK CARD

HCA

Short for Host Channel Adapter, InfiniBand's name for a network card. It is a small computer of its own. It reads memory, builds packets and handles retries in hardware, so the CPU can stay out of it. In GPU clusters each GPU usually gets its own HCA.

THE ROAD JUNCTION

Switch

Forwards packets. On the fast path it does exactly one thing. It looks up the destination in a table and sends the packet out the matching port.

THE ADDRESS

LID

Every port on the fabric gets a small number called a LID, short for Local Identifier. Each packet carries the LID it is headed to, a bit like an apartment number on an envelope.

THE BRAIN

Subnet Manager

A piece of software running somewhere on the fabric. It hands out every address and fills in every switch's table. More on why it exists in Part 6.

Part 5

Links never throw packets away

On Ethernet, a switch with a full buffer simply drops new packets. TCP on the sending computer eventually notices and resends. That works, but the waiting and resending hurts a lot when thousands of GPUs are all waiting on each other.

InfiniBand uses credits instead. The receiver tells the sender how much buffer space it has free. Each packet costs one credit. No credits means no sending, so the sender pauses until the receiver frees up space and hands a credit back.

This is called lossless flow control. Congestion makes senders wait, and nothing gets thrown away.

Part 6

Why the network needs a brain

Go back to the packet's trip in Part 3. It only worked because every port already had an address and every switch already had a full table. When you first power on a cluster, none of that exists.

So the Subnet Manager (SM for short) does the setup, roughly in this order.

  1. Explore. It sends special management packets out cable by cable to map every switch and HCA. These packets carry their own directions, like "out port 3, then port 17", so they work before any tables exist.
  2. Hand out addresses. Every port gets a LID.
  3. Plan routes. With the whole map in hand, it picks a path to every destination and spreads traffic evenly across the spines.
  4. Fill in every table, then switch the ports on.
  5. Keep watching. It re-checks the fabric regularly and reroutes around cables that die.

Why not let each switch figure things out alone, like Ethernet?

REASON 1

Better routes

Only someone who sees the whole map can spread traffic evenly over every spine. That even spread is what lets every GPU talk at full speed at the same time.

REASON 2

No gridlock

In a network that never drops packets, a bad set of routes can leave packets waiting on each other in a circle forever. Planning with the full map makes that easy to rule out.

REASON 3

Simple switches

All the thinking happens in one place, so the switches can stay dumb and fast.

What if the brain crashes? Traffic keeps flowing, because the switches keep their tables. The fabric just can't adapt to changes until a backup SM takes over, which is why real clusters run a standby.

Part 7

So what is UFM?

UFM (Unified Fabric Manager) is NVIDIA's software for running a big InfiniBand fabric. Think of it as the Subnet Manager plus a control room.

THE BRAIN

Runs the Subnet Manager

  • Hands out addresses
  • Plans routes
  • Fills in every switch table
THE CONTROL ROOM

Watches everything

  • A live map of every switch and cable
  • Health numbers per port, like errors and temperature
  • An alert log when a link flickers or degrades
  • Tools to switch off bad ports

On a big cluster that matters a lot. Instead of logging into hundreds of switches one by one, you deal with a single place.

Part 8

A real cluster

In June 2024 the AI company Imbue published From bare metal to a 70B model, a detailed write-up of bringing up their own training cluster from scratch. Here is roughly what it looked like.

4,088H100 GPUs
511servers, 8 GPUs each
400 Gb/sper GPU, each with its own HCA
320switches in 3 tiers

They describe InfiniBand as having "one brain for the entire network", which is the Subnet Manager from Part 6. A few of the problems they ran into make sense with the pieces above.

  • Renaming switches by location. One of their first jobs was working out which switch connected to which machines and renaming every switch after where it physically sat. Alerts say things like "port 12 on switch X", which only helps if X tells a technician which rack to walk to.
  • UFM couldn't see the switches. The SM discovers the fabric by walking cables. The top tier had been wired as eight disconnected networks instead of one, so there was no single fabric to discover.
  • Restarting UFM after mass reboots. Rebooting lots of GPU servers at once sends hundreds of ports down and back up together, which floods the brain with changes. Firmware upgrades could also corrupt its state. Either way, UFM needed a restart.
  • Parsing the UFM event log. All the flickering-link alerts land there, so Imbue scripted the loop of reading the log, disabling the ports involved, filing a repair ticket, and turning them back on once fixed.

Pocket glossary

Fabric
The whole InfiniBand network, all switches and cables together.
HCA
Host Channel Adapter. The smart network card.
LID
Local Identifier. A port's address on the fabric.
Forwarding table
A switch's lookup from destination LID to output port. Also called an LFT.
Credit
Permission to send one chunk, given by the receiver when it has buffer space.
Lossless
The network makes senders wait instead of dropping packets.
RDMA
Remote Direct Memory Access. One machine's card writes straight into another machine's memory without the CPUs.
GDR
GPUDirect RDMA. The same trick, but straight into GPU memory.
Fat tree
Leaves connect to every spine, so there are many equal paths between any two servers.
Subnet Manager
The brain. Assigns addresses and fills in every table.
UFM
NVIDIA's Subnet Manager plus monitoring, in one product.
